# 가격(HLOC) / 가격+거래량(HLOCV) 시계열만 입력으로 받는 네트워크

- 조사일: 2026-05-27
- 범위: 외부 정보(시총·공시·만기·뉴스·거시·시장지수 등) 없이 **자기 자산의 가격 시계열 또는 가격+거래량 시계열만**을 입력으로 받는 신경망 아키텍처
- 모태 조사: `.meta/260526-금융가격전용네트워크조사.md` 참조
- 표기: [확정] 검증된 사실, [추측] 추정·일반론, [근거, URL] 출처

## 0. 범위 정의

입력 텐서 형태가 다음 중 하나로 한정되는 모델만 다룬다.

- **U (Close-only)**: 종가 단일 채널, shape = (T, 1)
- **HLOC**: shape = (T, 4)
- **HLOCV / OHLCV**: shape = (T, 5)
- **OHLCV+turnover 등 거래소 raw 메타**: shape $= (T, \leq 7)$, 단 파생 기술지표·외부 변수 없음

제외 대상:

- 호가창(LOB, Level-2) 입력 모델 — 차원이 다르고 별도 카테고리 (DeepLOB, TLOB, LiT, BiN-CTABL, HLOB 등)
- 기술지표(MA, RSI, MACD, Bollinger 등)를 채널로 결합한 모델
- 시장지수·거시·뉴스·공시 등을 입력에 포함한 모델 (TFT, MASTER, FinMamba, MambaLLM 등)
- 멀티모달 (StockNet, BloombergGPT, FinGPT 등)

## A. OHLCV(또는 부분집합) 입력이 명시된 금융 특화 모델

### A.1 MambaStock (2024)

- **입력**: TuShare에서 받은 일봉 데이터에서 `close`를 타깃으로 분리하고, `pre_close, change, pct_chg` 및 date/code 컬럼을 제거한 나머지를 그대로 입력. TuShare 기본 컬럼 구성상 입력 ≈ **OHLV + amount(거래대금)** 5채널, 타깃 = close [근거, https://github.com/zshicode/MambaStock/blob/main/main.py 코드 인스펙션].
- **백본**: Mamba(S6) selective scan을 raw 입력에 그대로 적용. 수작업 특징 엔지니어링 없음 [근거, https://arxiv.org/abs/2402.18959].
- **출력**: 단일 종목의 다음 close (회귀).
- **분류**: 가장 깔끔한 "가격+거래량-only" 사례. 단일 종목 baseline.

### A.2 Stockformer (Wavelet, 2024)

- **입력**: "price-volume factor" 기반 입력 — 가격(OHLCV)에서 파생된 팩터를 사용 [근거, https://arxiv.org/pdf/2401.06139].
- [추측] 순수 OHLCV가 아니라 OHLCV에서 계산된 수익률·거래량 변화율 등의 팩터 조합일 가능성. 명시적 컬럼 리스트는 abstract에 없음 → 본 카테고리에 넣되 "[추측] 경계선" 표시.
- **백본**: Discrete Wavelet Transform으로 수익률을 고/저주파 분해 → Dual-Frequency Spatiotemporal Encoder + graph embedding → multi-task head (수익률 + 방향성).
- **출력**: 단기·장기 수익률 동시 예측, 종목 선정 헤드.
- **분류**: 입력은 OHLCV 도메인 안이지만 raw가 아닌 파생 팩터.

### A.3 PatchTST / iTransformer 류의 가격 도메인 직접 적용 사례

이 모델들 자체는 범용 시계열 모델이나, **금융 적용 논문에서 입력을 OHLCV 또는 종가만으로 한정**한 사례가 다수 존재한다.

- **VMD-PatchTST-ASWL (2024)**: S&P500, DJI, SSEC, FTSE 등 지수의 **종가 단일 채널**을 VMD(Variational Mode Decomposition)로 분해해 다중 모드 채널로 만든 뒤 PatchTST에 입력 [근거, https://arxiv.org/abs/2408.16707]. 즉 외부 정보는 없고 종가만 사용.
- **ICEEMDAN-PatchTST (NIFTY50, 2024)**: 동일한 패턴, ICEEMDAN 분해 → PatchTST → 포트폴리오 최적화 [근거, https://www.researchgate.net/publication/399102774].
- **PatchTST/iTransformer 자체**의 표준 벤치마크 중 ETT, Exchange 등은 다변량이지만, 금융 적용 논문은 자주 univariate close-only로 환원함 [추측].

### A.4 단순 회귀·딥러닝 baseline (가격만 입력)

상기 SOTA 모델과 별개로, 매우 흔한 baseline 패턴:

- **LSTM / GRU / CNN-LSTM stock prediction**: 학계·실무 모두 OHLCV-only 또는 close-only 입력의 변형이 수천 편 단위로 존재 [근거 일반론, https://arxiv.org/abs/2106.13008 등 서베이]. 본 문서에서는 개별 모델로 다루지 않음.
- **TCN / SCINet**: causal convolution baseline. 입력을 OHLCV로 설정한 금융 적용 사례 다수 [추측].

## B. 범용 시계열 모델 — OHLCV 적용 시 자연스럽게 가격-only 가능

이 그룹은 "가격 전용 설계"가 아니다. 그러나 입력을 OHLCV 또는 close-only로 한정하면 본 카테고리에 해당한다. 사용자의 가격 전용 네트워크 설계에서 **backbone 후보**로 가장 강한 풀.

| 모델 | 채널 처리 방식 | OHLCV 적용 형태 | 출처 |
|---|---|---|---|
| **PatchTST** (ICLR 2023) | channel-independence (각 채널 독립 univariate, 가중치 공유) | OHLCV 5채널 또는 close 1채널 | https://arxiv.org/abs/2211.14730 |
| **iTransformer** (ICLR 2024 Spotlight) | inverted view — 각 채널 = 토큰 | OHLCV 5토큰, attention이 채널 간 관계 | https://arxiv.org/abs/2310.06625 |
| **DLinear / NLinear** (AAAI 2023) | 채널별 단일 linear | OHLCV multichannel 그대로 | https://arxiv.org/html/2403.14587v2 |
| **FITS** (ICLR 2024 Spotlight) | rFFT→complex linear→iFFT | 채널 수 임의 (10k 파라미터) | https://arxiv.org/pdf/2307.03756 |
| **N-BEATS / N-HiTS** | 원형 univariate | close-only 단일 채널 | https://arxiv.org/pdf/2201.12886 |
| **TimeMixer** (ICLR 2024) | 순수 MLP, decomposable mixing | OHLCV multichannel | https://arxiv.org/abs/2405.14616 |
| **TimeMachine** | 4-Mamba quadruple, channel-mix/independent 통합 | OHLCV multichannel | https://arxiv.org/abs/2403.09898 |
| **S-Mamba** | 양방향 Mamba, FFN으로 temporal | OHLCV multichannel | https://arxiv.org/abs/2403.11144 |
| **xLSTMTime / xLSTM-Mixer** | sLSTM + mLSTM 결합 | OHLCV multichannel | https://arxiv.org/abs/2407.10240 |
| **RWKV-TS** | linear RNN, O(1) inference state | OHLCV multichannel | https://arxiv.org/abs/2401.09093 |
| **Chronos / TimesFM / Lag-Llama (zero-shot)** | 기본 univariate, 일부 covariate 옵션 | close-only가 기본, OHLCV는 멀티변수 변종 필요 | https://arxiv.org/abs/2403.07815, https://arxiv.org/html/2410.11773v7 |

### B.1 가격-only 한정 시 핵심 선택 축

- **Channel-independent (PatchTST)**: OHLCV를 5개의 독립 시계열로 봄. 변수 간 leverage·order 관계는 무시되지만 종목 간 일반화는 강함.
- **Channel-mixing / inverted (iTransformer, S-Mamba)**: O-H-L-C-V 간 관계(예: H-L = 일중 range, C-O = 일중 수익률, V와 |C-O|의 관계)를 attention/FFN으로 학습.
- **Univariate (N-BEATS, FITS, Chronos)**: close-only로 환원, 가장 미니멀. 거래량 정보 완전 폐기.

## C. 경계선: OHLCV + 파생지표 결합 (참고용)

이 카테고리는 본 문서의 엄밀한 범위 밖이지만, 자주 OHLCV 모델로 분류되는 경우가 있어 명시적 구분이 필요하다.

- **HAELT (2024)**: 입력에 OHLCV뿐 아니라 SMA·EMA·MACD·ADX·RSI·Stochastic·ROC·Williams %R·Bollinger·ATR·OBV·MFI·CMF·Force Index, 그리고 1-5 lag, rolling mean/std, ratio 등 **광범위한 engineered indicator를 포함** [근거, https://arxiv.org/html/2506.13981v1]. 뉴스 감성·거시는 future work로 명시적 제외. → **OHLCV-only가 아님**.
- VMD-PatchTST-ASWL, ICEEMDAN-PatchTST: close에 신호 분해(EMD/VMD)를 적용한 다중 모드 채널 사용. 외부 정보는 없으므로 **A 카테고리에 포함 가능**하지만, "raw OHLCV"는 아님.

## D. 입력 표현 패턴 정리

가격-only 모델들이 채택하는 입력 표현은 4가지로 나뉜다.

| 패턴 | 입력 형태 | 대표 모델 | 장점 | 단점 |
|---|---|---|---|---|
| **(1) Raw close 단일 채널** | (T, 1) | N-BEATS, FITS, TimesFM, Chronos | 가장 단순, 일반화 강함 | 거래량·일중 변동성 정보 손실 |
| **(2) Raw OHLCV 멀티채널** | (T, 5) | MambaStock, PatchTST 적용, iTransformer 적용 | OHLCV 간 관계 학습 가능 | 채널 스케일 불일치 대응 필요 (RevIN 등) |
| **(3) 수익률·변동률 변환** | (T, k) — r_t=log(C_t/C_{t-1}) 등 | Stockformer-Wavelet (price-volume factor) | 정상화 효과, fat-tail 보존 | 수준(level) 정보 손실 |
| **(4) 신호 분해 멀티모드** | (T, M) — VMD/EMD/wavelet 분해 후 M개 모드 | VMD-PatchTST-ASWL, ICEEMDAN-PatchTST, WPMixer | 다중 스케일·주파수 정보 명시화 | 분해 알고리즘 의존성, 분해 미래 leakage 주의 |

### D.1 [확정] 사실관계 (자료 기반)

- MambaStock의 입력은 close를 제외한 OHLV + 거래대금(amount) 5채널 [근거, 코드 인스펙션].
- HAELT는 OHLCV에 13개 이상의 engineered indicator를 추가 [근거, https://arxiv.org/html/2506.13981v1].
- VMD/ICEEMDAN-PatchTST는 close 단일 시계열을 신호 분해로 다중 채널화 [근거, https://arxiv.org/abs/2408.16707].

### D.2 [추측] 패턴

- "가격 전용"으로 분류되는 금융 특화 SOTA 논문은 의외로 적다. 대부분은 (a) covariate 추가, (b) cross-asset graph, (c) LOB 마이크로로 차별화함.
- 가격-only 설계 공간 자체가 연구 빈도가 낮다는 점에서 **신규 설계의 여지가 큰 영역**으로 보임.

## E. 가격-only 네트워크 설계에 대한 시사점

### E.1 입력 표현 결정

[확정 권고]
- **OHLCV multichannel + RevIN/FAN 정규화**가 raw 입력의 기본형. 단순성과 정보 보존을 양립.
- **거래량은 가격과 스케일·통계가 완전히 다름** → 채널 독립(PatchTST) 또는 채널별 정규화가 필수.
- **분해 채널(EMD/VMD/wavelet)**은 multi-scale 정보를 명시적으로 주입하지만, **rolling 방식이 아니면 미래 정보 leakage 발생**할 수 있음 [근거, 일반 신호처리 원리]. EWT/online 방식 채택 필요.

### E.2 백본 선택의 축

| 우선 검토 | 이유 |
|---|---|
| **PatchTST (univariate-per-channel)** | OHLCV 5채널의 분포 차이에 robust, 종목 간 일반화 강함 |
| **iTransformer (inverted)** | OHLCV 간 관계(H-L range, V와 변동성 등)를 attention으로 직접 학습 |
| **Mamba/Mamba-2 (causal SSM)** | 인과성 구조적 강제, 긴 시퀀스 효율 |
| **TCN/SCINet (causal conv)** | 가장 단순한 leakage-free baseline |
| **FITS / DLinear** | 극단적 최소 baseline, fair comparison용 |

### E.3 [확정] 회피해야 할 것

- TFT, MASTER, FinMamba, MambaLLM은 외부 정보 입력이 설계의 핵심 → 가격-only 시나리오에서 그대로 차용 불가. 단, **gating·decomposition 메커니즘만 추출**해 가격 내부 신호(예: 변동성 추정치)를 gating 신호로 재구성하는 응용은 가능 [추측].

### E.4 [확정] 강조해야 할 것

- 가격은 비정상·heavy-tail·자기상사 — RevIN의 affine 정규화는 fat-tail을 평탄화하므로 **FAN(주파수 적응 정규화)이 더 안전** [근거, https://proceedings.neurips.cc/paper_files/paper/2024/file/37c6d0bc4d2917dcbea693b18504bd87-Paper-Conference.pdf].
- 점 추정 head만으로는 부족 — quantile head 또는 mini SDE head로 분산·꼬리 정보 회수.

## G. 다음 단계 후보 ([추측])

1. **MambaStock 코드 실측**: TuShare 컬럼 정확히 확인 후 입력 스펙을 코드로 재현 (`.meta/` 또는 `experiments/` 폴더). 가장 깨끗한 baseline 확보.
2. **VMD-PatchTST 재현**: close-only + 신호 분해 패턴을 reproducible baseline으로 확보.
3. **iTransformer-OHLCV ablation**: OHLCV 5채널을 inverted attention으로 처리했을 때 H-L range, V-변동성 같은 채널 간 관계가 학습되는지 attention 시각화로 확인.
4. **거래량 채널의 효과 측정**: close-only vs OHLCV-multichannel의 동일 backbone 비교로 V 정보의 marginal gain 정량화.
