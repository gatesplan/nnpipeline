## 2. 문제 정의

[확정] 동기 — 시계열의 mean·variance가 시간에 따라 변하는 **distribution shift**가 예측 정확도의 근본 장애물 [근거, 논문 abstract].

[확정] 기존 instance normalization (DAIN·DAIN 변종 포함)은 입력 단에서 통계량을 제거할 뿐 — 출력 단에서 원래 스케일로 복원해줘야 하는데 이를 하지 않음. RevIN은 정규화·역정규화를 **대칭 구조**로 묶어 모델 양 끝에 배치 [근거, OpenReview + FAN 논문 §2.3 RevIN 서술].

## 3. 아키텍처

### 통계 계산 (per-instance per-channel)

배치 입력 $x \in \mathbb{R}^{B \times L \times C}$에 대해, 각 instance·각 채널별로 sequence 차원에서 평균·분산을 계산 [근거, RevIN.py 코드 `_get_statistics`]:

```python
def _get_statistics(self, x):
    dim2reduce = tuple(range(1, x.ndim-1))   # sequence dimensions
    self.mean = torch.mean(x, dim=dim2reduce, keepdim=True).detach()
    self.stdev = torch.sqrt(torch.var(x, dim=dim2reduce, keepdim=True,
                                      unbiased=False) + self.eps).detach()
```

[확정] `.detach()` 적용 — 통계는 **그래프에서 분리**되어 backprop을 통과하지 않음 [근거, 코드].

### 정규화 (입력 단)

$$\tilde{x}_{b,l,c} = \gamma_c \cdot \frac{x_{b,l,c} - \mu_{b,c}}{\sqrt{\sigma^2_{b,c} + \epsilon}} + \beta_c$$

코드 [근거, RevIN.py `_normalize`]:
```python
def _normalize(self, x):
    x = x - self.mean
    x = x / self.stdev
    if self.affine:
        x = x * self.affine_weight
        x = x + self.affine_bias
    return x
```

여기서 $\gamma_c, \beta_c$ (`affine_weight`, `affine_bias`)는 채널별 학습 파라미터:
```python
self.affine_weight = nn.Parameter(torch.ones(self.num_features))
self.affine_bias   = nn.Parameter(torch.zeros(self.num_features))
```

### 역정규화 (출력 단)

$$\hat{y}_{b,l,c} = \frac{\hat{y}'_{b,l,c} - \beta_c}{\gamma_c + \epsilon^2} \cdot \sqrt{\sigma^2_{b,c} + \epsilon} + \mu_{b,c}$$

코드 [근거, RevIN.py `_denormalize`]:
```python
def _denormalize(self, x):
    if self.affine:
        x = x - self.affine_bias
        x = x / (self.affine_weight + self.eps*self.eps)
    x = x * self.stdev
    x = x + self.mean
    return x
```

[확정] **affine reverse → stdev 곱 → mean 더하기** 순서가 핵심. 입력 단 통계를 그대로 출력에 복원하므로 distribution shift를 좌·우 대칭으로 "한 번 떼고 다시 붙이는" 구조.

### 사용법 [근거, 코드 README]

```python
revin_layer = RevIN(num_features)
x_in  = revin_layer(x_in, 'norm')
x_out = blocks(x_in)
x_out = revin_layer(x_out, 'denorm')
```

[확정] **임의의 layer 사이에 삽입 가능**하지만, 기본 사용 패턴은 모델 양 끝 (encoder 입력 / decoder 출력) [근거, README].

## 4. 핵심 inductive bias

[확정] RevIN의 가정 — 입력과 출력의 **trend statistic(mean/variance)이 큰 비중**으로 distribution shift를 설명한다 [근거, FAN 논문 §2.3 비판 부분].

[확정] 이 가정의 한계 — **trend는 다루지만 seasonal pattern은 다루지 못함** [근거, FAN 논문 §1, Fig.1 예시: 평균·분산은 동일하나 주파수가 변하는 신호에서 RevIN은 변화를 잡지 못함].

## 6. 한계

[확정] **Heavy-tailed / extreme value 데이터에 약함** — 후속 연구에서 MSE가 +683% 악화된 사례가 보고됨 [근거, FAN 논문 §2.3 한계 서술 및 외부 정리].
- 원인: instance 평균·분산은 outlier 1~2개에 크게 흔들리며, .detach()로 그래프 차단되어 backbone이 이를 보정할 학습 신호도 받지 못함.

[확정] **Seasonality 폐기** — 주파수 정보가 통계량에 흡수되지 않음. 평균·분산이 동일하고 주파수만 변하는 신호에서 RevIN은 정규화 효과를 제공하지 못함 [근거, FAN 논문 Fig.1].

[확정] **trend evolution을 무시** — 입력에서 추출한 mean/std를 그대로 출력에 더하므로, input·output 사이 trend가 변화하면 (regime shift) 오차가 누적됨 [근거, SAN·Dish-TS·FAN 모두 이 한계를 반박 motivation으로 사용].

## 7. 가격 전용 네트워크 설계에서의 시사점

[확정] OHLCV multichannel 입력에 RevIN을 채널별로 적용하면 **종목 간 가격 레벨 차이를 정규화 단에서 제거** 가능 — 1$ 주식과 100$ 주식이 backbone 입장에서 거의 같은 분포로 보임. DAIN과 유사한 효과지만 [확정] **역정규화로 출력 스케일 복원이 자동** 되는 점이 forecasting 회귀 태스크에 결정적 장점.

[추측] 가격은 fat-tail·heteroscedasticity가 심함 → RevIN의 affine 정규화는 평균·분산을 평탄화하는 과정에서 **꼬리 분포 정보를 손상**시킬 수 있음. quantile loss와 결합하거나 FAN으로 대체 검토 필요.

[확정] OHLC 부등식 제약, 거래량의 비대칭성, 가격 점프 등 가격 고유 구조는 RevIN이 다루지 않음 — 가격 전용 receptor라기보다는 "범용 정규화 + .detach()로 안정적 학습 신호 제공"에 가까움. 가격 receptor 설계 시에는 RevIN 위에 OHLC-aware reparameterization을 얹는 stacked 구조가 자연스러움 [추측].
